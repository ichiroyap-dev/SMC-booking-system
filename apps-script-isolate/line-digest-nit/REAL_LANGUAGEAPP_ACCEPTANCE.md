# 印尼文總覽：固定結構句＋中文備註

NO_DEPLOY。不要執行主通知、不要發送、不要寫表、不要 clasp push。

備註文法翻譯已放棄（Codex R8 否決 `740b13f` 之後，2026-10-12 決定）。這一版不把備註送進 LanguageApp。

## 現在怎麼翻

結構句用固定字串，不呼叫 LanguageApp：

- 時間標頭：`[Minggu 11 Oktober 2026 09:05 GMT+8] [Ringkasan Reservasi 11 Oktober 2026]`
- 時段與分區：午餐、晚餐、內用、外帶，以及桌數、筆數、桌數待確認
- 總計列
- 沒有預約的「無」→ `Tidak ada`
- 客人列的時間、稱謂（先生／小姐／女士）、`(外帶)`、人數待確認
- 名字欄上的方案代碼留在原位，例如 `(5k1a)`
- 整句相符的營運警示：大組訂位、純外帶日、舊的「今日預約正常」

「共」不留在印尼文計數。中文總覽那一半仍保留「共」。

時段、內用、外帶、總計只認中文總覽實際組出的整行。呼叫前會先去掉行首尾空白，格式裡面不能多字、也不能多空白。對不上的整行留中文原文並加一次提示。

接受的整行：

- 時段：`☀️ 午餐`、`🌙 晚餐`。這兩行後面不帶「共 N」。
- 內用：`🍽️ 內用 (共 N 桌)`（含 0）、`🍽️ 內用 (共 N 筆，桌數待確認)`、`🍽️ 內用 (共 N 桌，另 M 筆桌數待確認)`。
- 外帶：`🥡 外帶 (共 N 筆)`。只用「筆」。
- 總計：`(總計 內用 N 桌＋外帶 M 筆)`（含 0 桌）、`(總計 內用 N 桌，另 M 筆桌數待確認＋外帶 K 筆)`、`(總計 內用 N 筆桌數待確認＋外帶 M 筆)`。

不接受、因此留原文並加一次提示的例子：`(總計 內用 $1,000＋外帶 0 筆)`、`(總計 內用 2 桌待取消＋外帶 0 筆)`、`(總計 內用 無法確認＋外帶 0 筆)`、`☀️ 午餐 (共 3 桌)`、`🌙 晚餐 (共 2 筆，桌數待確認)`、單獨的 `🍽️ 內用`、`🍽️ 內用 (共 2 桌待取消)`、`🥡 外帶 (共 5 桌)`。這些行也不會打開客人區。

備註裡出現「☀️ 午餐」「🌙 晚餐」「(總計」不會被當成標題。客人列只在內用或外帶區裡拆。區外的店務文字，即使以時間開頭（例如 `14:00 水電先生來修冷氣`），整行留原文並加一次提示。稱謂只看姓名欄：`陳太太` 是 Ibu，備註裡的「先生」不改稱謂。

每一則非空白備註整段留中文原文，後面加同一句：

`REMARK_CONFIRM_NOTICE_` = `(Mohon konfirmasi dulu ke penanggung jawab)`（請先向負責人確認）

不切段、不查字典、不改標點、不改金額。`$1,000`、`NT$12,000`、`$1,000.50`、`$500,2隻雞` 都照來源留下，不改成 `$1.000`。方案代碼留在備註原文裡。

空白的 `備註：` 只變成 `Catatan:`，不加提示。只有方案代碼或數字的備註也留原文並加同一句提示。

已知警示後面若還有自由文字，固定句照翻，尾段連同分號留原文，再加一次提示。整句就是已知警示時不加提示。

店務維護那種整行自由文字同樣留中文並加提示。

客人姓名仍是中文。備註裡的「9大3小」「預估金額」「12點到」不抽出去另翻，整段留在中文備註裡。人數的固定譯法只用在客人列上的「人數待確認」。

## 不呼叫 LanguageApp

`LineDailyRemind.gs` 裡沒有 `LanguageApp.translate`。備註、店務自由文字、C 欄都不會送翻。

## 先前的真實驗收（歷史，不是這一版的做法）
