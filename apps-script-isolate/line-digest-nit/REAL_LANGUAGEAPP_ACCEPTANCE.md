# 真實 LanguageApp 驗收清單

NO_DEPLOY。這是部署前要在獨立測試專案做的清單，不是授權。不要執行主通知、不要發送、不要寫表、不要 clasp push。

離線 stub 通過不能代替這份清單。金額 token 留著，也不等於印尼文語意已通過。

## 測試環境

獨立測試 Apps Script，只呼叫這三個函式：

- `translateTaskCnToId`
- `translateNoteCnToId`
- `buildDailyReminderMessage_`

不執行主通知、不送 LINE、不寫試算表。

## 金額

六個入口都測：B 欄備註、總覽整行 fallback、C 欄一般翻譯、固定大組警示加尾段、純外帶警示加尾段、舊「今日預約正常」句加尾段。

各測 `$1,000`、`NT$12,000`、`$1,000.50`。來源 token 要逐字留下、只出現一次，不改千分位，也不自行補幣別。原文若是全形逗號，就保留全形逗號。

多段 `訂金$1,000已付；尾款NT$12,000元；找零$1,000.50已付`，以及單段 `訂金$1,000尾款$2,000`。核對已付／未付，以及每個金額的位置。不能出現誤導的 `Rp` 或其他幣別。審查樣本裡的 `Rp` 不是真實 Google 行為，不能當成品質通過。

## 方案代碼

`加點5k1a一份`、`5k1a；花生過敏`、`不要5k1a改成6k1a`。取消與改用不能混在一起。

## 維護提醒（F-1，先採方案 a）

整行 fallback 會在逗號等分隔符切段。`清洗製冰機，下午三點前完成，並拍照回報` 會分成三次送翻：`清洗製冰機`、`下午三點前完成`、`並拍照回報`。金額保護不受這次切段影響，但跨段語意要看真實翻譯。

先比較 2 到 3 則實際維護提醒的整句翻譯與切段翻譯。至少包含期限、條件或否定。可用：

- `清洗製冰機，下午三點前完成，並拍照回報`
- `若發現漏水，不要啟動，先通知店長`

條件的作用範圍、順序、期限、否定和回報要求必須一致。

若語意變差（期限、條件、否定或回報要求對不上），這次部署驗收不通過。那時才改採方案 (b)：整句做 token 保護與完整性檢查，保留一次翻譯，不要先切段。方案 (b) 要改程式，並重審新的 head。目前沒有證據要求先改。

## 混合警示

固定警示和尾段之間的換行可能變成 `; `。固定句不在開頭時改走機翻。C 欄翻譯失敗時，中文標點仍會被正規化。這些要看完整語意，不能只因為金額還在就判定整句正確。

另外測：大組警示加換行再加金額、金額在前而警示在後、純外帶再加另一則警示、舊格式「包含12人」、C 欄多行與標點。整則訊息要完整，員工要看得懂。

## 原清單保留

品項數量、9 大 3 小、啤酒與時間、`$500,2隻雞`、`不要辣,300份`、`|` 與括號、純英文、空備註、原文 `{{0}}`、過敏與否定。

## PUA

保存原輸入、實際送進 LanguageApp 的文字，以及輸出。記錄每段是否留下私用區字元、是否退回中文。真實 token 被改寫，或關鍵金額、方案、過敏段落看不懂，就停在驗收，留下證據。

## 完整忙日

分開記錄 B 欄與 C 欄的呼叫數、實際耗時、雙語總長度。離線 fixture 的 11 次只是那個樣本的 B 欄結果，不能當成所有忙日的上限。

C 欄傳 null cache，沒有整欄配額停止旗標。每日配額錯誤之後，每個中文分段仍可能再呼叫一次；不重試、不暫停。忙日驗收要把這些呼叫算進去。

每日配額、短時間限流，以及 token 刪除、錯號、複製，繼續用 stub。不要故意耗光真實額度。

## 長度與耗時

保存完整雙語長度與實際耗時。LINE 單則 text 上限 5,000。Apps Script 一般執行限制目前是 6 分鐘，要留下餘裕。
