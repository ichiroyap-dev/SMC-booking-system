# 訂單欄怎麼存

這份給店務和之後移植正式腳本用。沒有掛在官網選單。`SEND_ATTRIBUTION_TO_BACKEND` 維持 `false`。這輪不寫正式試算表，也不部署。

同一列在鎖內先 `values.get` 整張分頁的公式（`valueRenderOption=FORMULA`，不設 `A:ZZ` 上限），再用 `values.update` 寫到最後一筆有值的下一列。`=""` 也算有資料。回應的 `updatedRange` 要是這張分頁、正好那一列、欄從 A 到這列最後一欄。記錄裡的 `tableRange` 是推算。`valueInputOption` 固定是 `RAW`。Google 只保證 RAW 不解析輸入，不是說 `+`、`-`、`@` 一定會被當成公式。字串會維持文字；數字要傳數字，日期要傳試算表序號，RAW 才不會把它們也存成文字。

序號是從 1899-12-30 起算的天數，表示試算表時區的牆鐘，不是 UTC 瞬時。`2026-10-18T07:00:00Z` 在台北是 15:00。日期是整數。時間是一天的分數，`12:00` 是 `0.5`。收到時間是日期加時間。讀回若拿到 Date，用 `Utilities.formatDate` 和 `getSpreadsheetTimeZone()` 換回同一個序號，不用專案時區，也不拿 UTC 瞬時去對。

不像該欄的值就留成 RAW 文字，不改成 0，也不改走會執行公式的寫法。

| 欄 | 怎麼存 | 原因 |
|---|---|---|
| 訂單編號 | RAW 文字 | 識別碼，不可拿去加總 |
| 收到時間 | 日期時間序號，格式 `yyyy-mm-dd hh:mm:ss` | 系統產生，要能排序 |
| 動作 | RAW 文字 | 固定代碼 |
| 類型 | RAW 文字 | 固定代碼 |
| 姓名 | RAW 文字 | 客人自由文字。開頭的 `'` 保留 |
| 電話 | RAW 文字，格式 `@` | 一定保留開頭的 0，禁止存成數字 |
| 信箱 | RAW 文字 | 自由文字 |
| 人數 | 數字，格式 `0` | 店務要加總。不是整數就留文字 |
| 桌數 | 數字，格式 `0` | 同上 |
| 日期 | 日期序號，格式 `yyyy-mm-dd` | 日期篩選。不是 `YYYY-MM-DD` 就留文字 |
| 時間 | 時間序號，格式 `hh:mm` | 時段排序。不是 `HH:mm` 就留文字 |
| 備註 | RAW 文字 | 客人自由文字。開頭的 `'` 保留 |
| 品項 | RAW 文字 | 自由文字 |
| 來源到點擊識別碼共 9 欄 | RAW 文字 | 可能以 `=`、`+`、`-`、`@` 開頭，必須原樣 |

客人信仍顯示 `2026-10-22`、`12:00`、人數 `2` 這種讀得懂的文字。格子裡的序號不直接貼進信。

電話若被存成數字，開頭的 0 會消失，店務回撥會錯。所以電話永遠是文字。電話與其他文字欄不加前導單引號；客人自己打的 `'` 留著。

## 若把數字和日期先轉成文字再 RAW

現行程式**不要**這樣寫。`values.update` 的 `RAW` 不解析輸入：傳字串就存成文字，傳數字才是數字，傳序號才是日期或時間。下面是「先 `String()` 再 RAW」的效果，用來對照預期型別。

| 欄 | 現行程式的儲存格型別 | 全文字 RAW 的儲存格型別 | 全文字的影響 |
|---|---|---|---|
| 人數 | 數字（整數才是數字，否則文字） | 文字，例如 `2` | 加總會漏掉文字 |
| 桌數 | 數字（整數才是數字，否則文字） | 文字，例如 `1` | 同上 |
| 日期 | 日期序號（數字） | 文字，例如 `2026-10-22` | 不能當日期篩選 |
| 時間 | 時間序號（一天的分數） | 文字，例如 `12:00` | 不能當時段排序 |
| 收到時間 | 日期時間序號（數字） | 文字，例如 ISO 字串 | 排序變成字典序 |

客人信仍用讀得懂的文字，不把序號貼進信。
